## Model 1 — Random Forest

Bagging

Responsible person: Sameera — Member 1

Random Forest trains multiple decision trees using different bootstrap samples of the training data and randomized feature subsets. Their predictions are aggregated to produce a final classification or probability estimate.

- Learning approach: Bagging (Bootstrap Aggregating).
- Main purpose: Reduce variance and improve generalization compared with relying on a single decision tree.
- Why it fits CargoSense: It can learn nonlinear relationships between truck capacity, proposed cargo, inventory, demand and route characteristics.
- Expected output: Predicted probability or score for `Became_FTL = 1`.

## Model 2 — XGBoost

Boosting

Responsible person: Member 2

XGBoost builds an ensemble of decision trees sequentially. Each new tree helps improve the ensemble's predictions by optimizing an objective function using gradient boosting.

- Learning approach: Gradient boosting.
- Main purpose: Build a strong predictive ensemble by iteratively improving the model's objective.
- Why it fits CargoSense: It can capture complex interactions among demand, available inventory, remaining capacity and candidate cargo characteristics.
- Expected output: Predicted probability or score for `Became_FTL = 1`.

### Why are we choosing these two models?

Our dataset is structured operational tabular data. The relationship between a candidate's features and its eventual outcome may be nonlinear. For example, a candidate might have sufficient remaining weight capacity but insufficient volume capacity, or the inventory may be available while destination demand is too low.

Tree ensembles can learn these kinds of interactions without requiring us to specify a linear relationship in advance.

| Comparison         | Random Forest                                | XGBoost                                                            |
| ------------------ | -------------------------------------------- | ------------------------------------------------------------------ |
| Ensemble technique | Bagging                                      | Boosting                                                           |
| Tree construction  | Trees trained independently                  | Trees added sequentially                                           |
| Primary mechanism  | Aggregates tree predictions                  | Optimizes the ensemble iteratively                                 |
| Main tuning areas  | Number of trees, depth, split and leaf sizes | Number of boosting rounds, learning rate, depth and regularization |
| Key comparison     | Generalization and variance reduction        | Predictive performance through iterative optimization              |

Neither model is guaranteed to perform better. The held-out test results will determine which is more suitable for this dataset.

## 6. Evaluate both baseline models

Do not compare the models using accuracy alone. A model could achieve high accuracy simply by predicting the majority class when successful FTL conversions are relatively rare.

Use the following metrics:

| Metric           | What it tells us                                                                |
| ---------------- | ------------------------------------------------------------------------------- |
| Accuracy         | Overall proportion of correct predictions                                       |
| Precision        | Of the candidates predicted to become FTL, how many actually did?               |
| Recall           | Of the candidates that became FTL, how many did the model identify?             |
| F1-score         | Balance between precision and recall                                            |
| Confusion matrix | Counts true positives, true negatives, false positives and false negatives      |
| PR-AUC           | How well the model ranks positive candidates across precision-recall thresholds |

For CargoSense, precision and recall have practical implications:

- Low precision: The ODE may prioritize many candidates that do not subsequently become FTL.
- Low recall: The ODE may miss many opportunities that would become FTL.
- High F1-score: A useful balance between precision and recall, although the final priority depends on operational costs.
- High PR-AUC: Potentially useful ranking performance when positive outcomes are uncommon.

Also compare probability calibration if the scores will be interpreted as probabilities. A predicted probability of 0.8 should not automatically be assumed to mean an 80% success rate without checking calibration.

For XGBoost:

Also consider SHAP explanations if the team has time and the implementation is reliable.

Tasks:

2. Check whether the important features are operationally plausible.
3. Investigate suspicious importance assigned to identifiers, timestamps or proxy variables.

Feature importance can be misleading when features are correlated, so use it as an interpretability aid rather than definitive evidence.

## 11. Select the model for Phase 10

Do not automatically select XGBoost because it is more complex, or Random Forest because it is easier to explain.

Choose based on:

- Held-out predictive performance.
- Precision-recall trade-offs.
- Ability to rank useful candidates.
- Stability across relevant time periods.
- Probability calibration, if probabilities drive prioritization.
- Inference time and deployment complexity.
- Interpretability and maintenance requirements.

The business may prefer higher precision if false recommendations are expensive, or higher recall if missing a valuable consolidation opportunity is more costly. Document the trade-off.

The selected model will supply a probability or score to Phase 10. It will not generate SKU combinations, guarantee FTL conversion or replace hard feasibility rules.

## What happens in Phase 10?

Phase 10 integrates the chosen model into the operational Opportunity Detection Engine:

1. Generate candidate cargo combinations using the Phase 6 candidate-generation logic.
2. Filter candidates that violate hard constraints, including route compatibility, inventory availability, open demand, payload capacity and volume capacity.
3. Pass eligible candidates through the saved Phase 8 preprocessing pipeline and selected Phase 9 model.
4. Score candidates using the model's predictions.
5. Rank the candidates according to the chosen business priorities.
6. Produce the final dispatch recommendations with explanations and feasibility checks.

The important separation is that Phase 6 generates opportunities, Phase 9 predicts their likely outcomes, and Phase 10 turns eligible scored opportunities into ranked recommendations.
